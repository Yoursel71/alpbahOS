These results are for ISO r21 only. Rounds 22 to 25 changed GRUB, Plymouth, the desktop profile and the Welcome app,
so the matrix has to be run again on the newest ISO; nothing here carries over to r22-r25.

- ISO: `scratch-lfs-bench/images/alpbahos-beta-0.9-2026-11-09-r21.iso`, sha256
  `46634e492a2c433dece0d951ff355ff6faf93a1de59f66cd739942884b0e1150` (recomputed, `matrix/iso-sha256.txt`).
- Host `thewo`, QEMU 10.2.2, KVM with `-cpu qemu64`. Guests ran 2026-11-10 20:02 to 20:29, at most three at a time.
- Evidence: `scratch-lfs-bench/lfs13-logs/iso-beta-0.9/r21/matrix/` (not in the repo); verdict file
  `results21.tsv` in that directory. Paths below are relative to it.
- Installed rows used reflink copies of `inst-bios-msdos-r21.raw` and `inst-uefi-gpt-r21.raw`; the two kept images
  were opened read-only or copied, never booted.
- Harness: commit `17e409d` (`scripts/rebuild/r21/matrix-r21.sh` and helpers; switches in `vm-start.sh`,
  `diag-r21.sh`, `r20-lanes.sh`).
- The run was cut short: the task changed to "no new guests" before L2, L4, KF and F1 started. Verdicts were written
  on 2026-11-11 from the evidence on disk; each PASS names the file that was opened.

## 2. S1: shutdown cycles

One reflink copy (`S1-disk.raw`), written to by all three boots. Each cycle: greeter login typed through QMP, the
test user's session up for about 96 s without input, then the call.

| Cycle | Method | Power-off | Time |
|---|---|---|---|
| 1 | `busctl --user call org.kde.Shutdown /Shutdown org.kde.Shutdown logoutAndShutdown`, as testuser with the session environment | `S1-c1/qmp-events.log`: `SHUTDOWN {"guest": true, "reason": "guest-shutdown"}`, then EOF; no QMP quit sent | 6 s |
| 2 | the same call | `S1-c2/qmp-events.log`: the same | 5 s |
| 3 | `systemctl poweroff` as root | `S1-c3/qmp-events.log`: the same | 5 s |

- The interface was introspected before each call (`run-S1.out`): `org.kde.Shutdown` with `logout`,
  `logoutAndReboot`, `logoutAndShutdown`, `saveSession`. The journal of cycles 1 and 2 has
  `systemd-logind: poweroff requested from client PID ... ('plasma-shutdown')`. This is the call the Plasma logout
  screen makes after the user confirms; the menu and the confirmation screen themselves were not clicked.
- The times include a 5 s stop timeout of the test shell unit (`r21m-agent.service: Failed with result 'timeout'`,
  my instrumentation), so the product's own shutdown time is not measured.
- After each cycle, read-only mount of the copy (`check-S1-disk-c1..c3.txt`, `shutdown-lines-S1-disk-final.txt`):
  `/var/lib/systemd/coredump` exists and is empty (0 entries); ext4 mounted clean; three boots in the journal, each
  ending with `Journal stopped`. Lines per boot for `dumped core`, `segfault`, `code=dumped`, `ABRT`, `SEGV`,
  `core-dump`: 0. The two `core dump` matches per boot are the unit lines `Listening on / Closed Process Core Dump
  Socket`.
- **Coredump at shutdown: not reproduced in 3 cycles.** This does not show it is fixed.
- Lines that do fail at shutdown:
  - `alpbahos-zram.service` fails on stop in all three cycles: `zram-swap: swapoff: /dev/zram0: takas kapatma
    başarısız: Geçersiz argüman`, `Control process exited, code=exited, status=4/NOPERMISSION`, `Failed with result
    'exit-code'`. Product defect, not fixed here (the swap is probably already off when the stop command runs; not
    checked).
  - `obex.service: Main process exited, code=exited, status=1/FAILURE` in cycle 1 only (user unit).
  - `Failed to enqueue SYSTEMD_WANTS job` lines for the sound card and rfkill devices (systemd refusing start jobs
    during shutdown).

## 4. REC1 and REC2: recovery from the live ISO

Copies `REC1-broken.raw` (BIOS) and `REC2-broken.raw` (UEFI): `/boot/initramfs-7.1.8-alpbahos.img` removed and
`/boot/grub/grub.cfg` truncated to 0 bytes, in the copy only (`REC1-break.txt`, `REC2-break.txt`). Live ISO booted
first (`-boot order=dc`) with the copy as the virtio disk; under OVMF this also booted the ISO.

How the tool starts on r21 (`REC2/rec-1-path.png`, `rec-2-list.png`):

- The live user's `PATH` is `/usr/bin:/opt/qt6/bin`; `alpbahos-recover` is not found by name.
- `sudo -n true`: `sudo: a password is required` (the live user has no password), so the tool's own usage line
  `sudo alpbahos-recover ROOT_PART [ESP_PART]` cannot be followed in the live session.
- `pkexec /usr/local/sbin/alpbahos-recover <root> [<esp>]` works without a prompt (live polkit rule).

The repaired copies, booted alone, reach the SDDM greeter: `REC1-boot/rec-disk-greeter.png` (20:29),
`REC2-boot/rec-disk-greeter.png` (20:23, OVMF).

The two `write error` lines (seen in both rows, as in round 19):

- "Veri alınamıyor" is the Turkish glibc text for EPIPE (broken pipe), checked on the host with
  `os.strerror(errno.EPIPE)` under `tr_TR.UTF-8`.
- Line 33 of `target-initramfs.sh` is `echo "$LIST" | grep -q "/$m\.ko" || grep -q ... "$BUILTIN" || ...` inside
  `for m in ahci nvme sd_mod virtio_blk`. `grep -q` exits at the first match while `echo` is still writing the long
  `lsinitrd` listing.
- `REC1/rec-5-sigign.png`: `SigIgn` is `0000000000000000` in the Konsole shell and `0000000000001000` under
  `pkexec`: bit 13, SIGPIPE, is ignored for everything pkexec starts. So `echo` gets EPIPE and prints an error
  instead of being ended silently by the signal.
- Two lines because two modules (`ahci`, `nvme`) are found in the image; `sd_mod` and `virtio_blk` are built in, so
  `grep` reads that listing to the end. This last point is inferred from the script comment, not measured.
- Effect: none on the result (the pipeline's status is grep's; the steps after it ran and the disk boots). Not
  fixed here.

## 5. Findings (not fixed)

1. `alpbahos-zram.service` fails on stop at every shutdown (section 2).
2. No ALSA command-line tools in the image (`aplay` missing); the U2 `aplay -l` check cannot be done on r21.
3. The recovery tool's usage text says `sudo`, which does not work for the live user; the tool is not in the live
   `PATH` (section 4).
4. `write error` lines in recovery step 3: SIGPIPE ignored under pkexec (section 4).
5. `obex.service` exits 1 at session end (seen once in three cycles).
6. `/boot/initrd.img-7.1.8` (39,490,526 bytes, dated 7 Nov) is in both installed systems next to the initramfs that
   GRUB uses; whether anything needs it was not checked.
7. Earlier R1 records overstate their evidence (section 3).

## 6. Deviations and what was not tested

- NOT RUN on r21: L2, L4 (TCG live rows), KF (keyboard F end to end), F1 (forced failure with the changed cleanup
  script). No image was created for KF or F1.
- Installed rows (B2, B3, U2, FP-GUI, S1, R1) used test instrumentation on reflink copies: the `diag-r21.sh` one-shot
  unit for B2, B3, U2, and a root test shell on a second serial port (`r21m-agent.service`) for FP-GUI, S1 and R1.
  Nothing was typed into the installed desktop; the greeter password was typed through QMP.
- S1 and R1 called the session interface directly; the Plasma menu and its confirmation screen were not used.
- B2: that the root disk is on AHCI is taken from the QEMU command line (one disk, on `ahci0`), not from a guest
  listing.
- FP-GUI: Flatpak was installed system-wide by root; the app was started as testuser by `systemd-run --uid` with
  the session's environment, not from the launcher.
- Not tested at all: real hardware, real Wi-Fi, an IPv6 inbound probe, frame time.
- A first exploration boot (`PROBE0/`) is not a row.

Beta gate (QEMU level) on r21: NOT MET (L2, L4, KF, F1 not run; `aplay -l` not proven).
Open items: PERF-01 (1116 to 1126 MiB idle at 4G against the 1024 MiB target); coredump at shutdown not reproduced
in 3 cycles, not proven fixed; ALP-TRUST-01 code in progress on another branch; APPARMOR-01 backlog only; the D108
visibility conflict; the real-PC test is the user's.

## 7. Running the harness on a newer ISO (for example r25)

`scripts/rebuild/r21/matrix-r21.sh <sub-command>`; every sub-command refuses an existing run directory or target.

What is a variable today: `MATRIX_DIR` (evidence directory), `RECWAIT` (seconds given to the recovery run),
`FAILSHOTS` (minutes watched in F1); for `vm-start.sh`: `NO_REBOOT=0`, `NVME_BOOTINDEX`, `EXTRA_ARGS`, `NIC`,
`ACCEL`; for `diag-r21.sh`: `OUTD`, `BUS`, `MEM`, `DIAG_HOOK`, `FLATPAK`, `NIC_NONE`.

What is still hard-coded and must be edited (or turned into variables) first:

- in `matrix-r21.sh`: `ISO`, `IMGB`, `IMGU`, `PWF` (all `...-r21...`), the KF and F1 image names (`...-r21m.raw`) and
  the KF secret file name;
- in `diag-r21.sh`: the password file `test-secrets/r21.pw`;
- `cmd_f1` passes `ROUND=r21` to `r20-lanes.sh` (it selects the password file).

Order that worked: `sha`; `live L3 bios kvm 180`; `diag B2`, `diag B3`, `diag U2`; `s1`; `r1`; `fpgui`;
`recprep`/`reclive`/`recboot` for REC1 (`bios REC1 /dev/vda1`) and REC2 (`uefi REC2 "/dev/vda2 /dev/vda1"`); then
`kflive`, `kffill`, `kfgo`, `kfdisk`, `kfboot` or `kfagent`; `f1`; last and alone `live L2 uefi tcg 900` and
`live L4 bios tcg 900`. New installs (I1, I2) still come from `r20-lanes.sh`.

Known gaps:

- `kflive`, `kffill`, `kfgo`, `kfdisk`, `kfboot`, `kfagent`, `f1` and `rofacts` were written but never run.
- No sub-command writes a verdict; `results21.tsv` is written by the reviewer.
- `live` takes a screenshot every 30 s and does not detect the desktop; the reviewer picks the first frame.
- The test shell unit adds a 5 s stop timeout to every shutdown and fails with `timeout`; a fix (end the shell on
  SIGTERM) would give real shutdown times.
- `check` reads only the last boot; after a QMP quit the copy is not clean and the last boot is missing (R1).
- Lane waiters must not use `pgrep -f <pattern>` inside `sh -c` with the same text (it matches itself); wait on a
  line in the lane's output file instead.
- Round 24/25 removed the KDE Welcome Center and changed GRUB and the splash: the fixed waits (80 s live, 60 s
  repaired disk) and the greeter click position (766, 489) need a look on the new ISO.

Rows that still need the GUI (typed keys and screenshots): the live rows; REC1/REC2 (Konsole in the live session);
KF (keyboard tool, Calamares, physical keys in the installed session); F1 (Calamares, error dialog); every greeter
login. Text-only through the instrumented copy: B2, B3, U2, S1, R1 and the facts of FP-GUI (its window needs one
screenshot).
