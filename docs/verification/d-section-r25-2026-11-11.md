## Failed attempts (kept for the record)

- r23: every install stopped at the new `shellprocess@grub-gfxmode` step: Calamares 3.3.14 does not expand `@@ROOT@@`
  (already noted in live-layout-copy.sh). Fixed by finding the target by its mount. The r23 install images were removed.
- r24: the Welcome app failed to load its QML ("Module AlpbahHosgeldin contains no type named Main",
  `NO_RESOURCE_TARGET_PATH`); the KDE Welcome Center still opened (the kded6rc switch alone did not stop it); apps
  stayed light (Plasma 6.7 applied wallpaper and layout but only the colour scheme name). Fixed in r25 (records
  `alpbah-hosgeldin-r25`, `alpbahos-desktop-profile-r25`). The installed kernel line had `splash splash`: Calamares adds
  `splash` itself when plymouth is in the target; kernel_params is back to `[ "quiet" ]`.
- r24: the host disk filled up during the UEFI install (17 MB free); that install was discarded and old ISOs and
  installs of rounds 22-24 were removed. r25 was run with 78 GB free.
- r25 first pass: the GRUB mode rows looked for `set gfxmode=auto` (now `1280x800,auto`) and the shutdown burst took a
  frame every 0.2 s (the guest is off after 0.42 s). Both tools fixed and the rows run again (PASS above).
- Plymouth first build: its version script reads the version from the source directory name; build-pkg-r10.sh got an
  opt-in `BLD_NAME`.
- dracut pulled every GPU driver (221 MB initramfs) until `UseSimpledrm=1` was also in `plymouthd.defaults` (dracut
  reads only that file for a generic image).

  a second (black box on UEFI). Planned: `background_color` and no "Loading" echo lines (round 26).
