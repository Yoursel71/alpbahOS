## 2. Method

- Build root: `scratch-lfs-bench/r4-root`, a writable btrfs snapshot of `r3-root` made by the driver on
  first run. TEMP-01 was not applied, so the base still has the 1596 perl files (they are in use).
- Per package (`scripts/rebuild/r4/run-r4.sh`):
  1. Source copied from `blfs-plan/blfs-src`. Its md5 must equal the md5 on the BLFS page (`packages.tsv`).
     Upstream does not publish a sha256 in this repo, so the sha256 is recorded as **TOFU**.
  2. Script from the test image's generator (`blfs-plan/gen_blfs_chroot.py`, the same file as
     `scripts/lfs-blfs/gen_blfs_chroot.py`), with `export LANG=C LC_ALL=C` added at the top.
  3. Chroot build. The BLFS commands run `make install` directly into the root, so **no DESTDIR**.
     This is the fallback method (R3 snapshot diff) for every package in batch 001-030.
  4. Read-only snapshots before and after the build; `r3_ledger.py diff`; manifest of the added or
     changed files (`r4_lib.py manifest`, schema `alpbahOS.package-files/v1`).
  5. `alp adopt-base --root r4-root` with that manifest, the name, the version and the sha256. The
     records are `lfs-base` and protected: **not removable as normal packages.** This is a deviation from
     D141 and the test image, and it stays until packages have real DESTDIR recipes.
  6. ISA audit (`audit-isa.sh`, default exit code) on the new ELF files.
  7. One line in `scratch-lfs-bench/r4-status.txt`.
- The batch stops at the first FAILED package. Re-running resumes after the last OK line.

## 3. Decisions taken on the way (use the earlier test image's choice)

- **Build locale C.** `/etc/locale.conf` in the base is `tr_TR.UTF-8`. In that locale `sed 's/[a-z]/.../'`
  does not match `i`, and the p11-kit generator wrote `vo_d` for `void` (003, first try). `LC_ALL` passed
  to `chroot` did not survive `bash --login`, so the generated script exports `LANG=C LC_ALL=C` itself. The
  target system keeps its locale. The test image ran without a Turkish locale.
- **Resolver in the chroot.** `etc/resolv.conf` links into `/run/systemd/resolve`, which the chroot did not
  have. The driver bind-mounts that directory. Without it `make-ca -g` cannot fetch `certdata.txt` (004,
  first try).
- **Hook files excluded from manifests:** `usr/share/info/dir` (owned by cpio in the base) and
  `etc/ld.so.cache`. They are rewritten by install-info and ldconfig. Without the exclusion `alp adopt-base`
  refused 001 with "sahiplik çakışması" (ownership conflict on `usr/share/info/dir`).
- **Fresh build directory** per try (`sources/blfs-build/<name-version>` removed first). Meson keeps
  generated files in its build directory; the first p11-kit try left its bad header behind.

curl 8.15.0 does not compile against the base's OpenSSL. The errors are `invalid use of incomplete typedef
'ASN1_INTEGER'` in `vtls/openssl.c` (OpenSSL 4 made those types opaque). The base has **OpenSSL 4.0.1**
(`openssl version`). The test image used **OpenSSL 3.5.2** (`docs/verification/m04-base-ownership-assessment-2026-09-23.md`
line 15). R4 cannot pass 006 without one of these, which is a decision for the coordinator:

1. Rebuild OpenSSL 3.5.2 in r4-root (replaces the R3 base's OpenSSL 4.0.1 record; it changes libcrypto
   for every package above it, and the R3 ISA and boot results would need repeating), or
2. Move curl to a version that builds on OpenSSL 4 (new source, new checksum, not in the book version).

Packages after 006 were not started, because the driver stops at the first failure and dependencies are
not recorded in `order.txt`. A second driver mode that skips dependants of a failed package is not written.
