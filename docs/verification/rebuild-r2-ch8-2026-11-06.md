## 5. qemu user-mode method and negative control

Gate: `qemu-x86_64 -cpu qemu64` (and `qemu32`) is the baseline; `-cpu max` is the feature-rich reference. The host (AMD Ryzen 7 5700, Zen 3) has no AVX-512.
Scripts: `scratch-lfs-bench/isa-src/` (`isa-run.sh`, `neg-run.sh`, `final2.sh`, `cov2.sh`); outputs `scratch-lfs-bench/lfs13-logs/isa/`.

Negative control (`isa/neg{64,32}.{adx,avx2,bmi2,avx512}.{qemu64,qemu32,max}.err`): AVX2, BMI2 and ADX test programs give `qemu: uncaught target signal 4 (Illegal instruction)` (rc 132) under qemu64/qemu32 and run (rc 0) under max. AVX-512 gives rc 132 everywhere because the host has no AVX-512, so AVX-512 paths are untested (AVX512-COVERAGE).

Method. A run that completes with rc 0 under qemu64 did not execute any routine that contains a trapping instruction on the path it took. Output correctness is checked where the test has a reference (KAT, round trip, cross-verify). Speed runs (`openssl speed`) only prove that no trap happened; they do not check the result.

Known limit. A routine is only proven unreachable for the tested paths. Calls from paths not exercised by these tests are not covered. The audit call-graph rule does not apply to exported or address-taken symbols.

Runs (isa/summary.txt, isa-final.stdout, isa/cov2-summary.txt):

- KAT (`kat64`, `kat32`): sha256, sha512, aes128-cbc, P-256 point (`p256_1G_x`), X25519 RFC 7748 vector: PASS on qemu64, qemu32 and max.
- atomic16 (`libatomic` 16-byte load/store): PASS on qemu64 and max.
- pyvec (CPython `_blake2`/`_hmac` vectors): PASS on qemu64 and max.
- Keyed blake2b (`b2key.py`): qemu64 output identical to host python output (`B2KEY 12f0b4a4...7b104b3aff951614`).
- zstd -3 compress/decompress of 100 KB, cmp equal (`ZSTD_S3_SAME`), qemu64 and max.
- base64 encode/decode of 1 MB random data: sha256 equal, qemu64 and max.
- sm4-cbc speed (rc 0), openssl speed AES/RSA/P-256 (rc 0; speed runs only).
- Round trips (`cov2-summary.txt`): AES-256-CTR, AES-256-CFB, AES-128-CFB, AES-256-CBC, SM4-CBC: qemu64 ciphertext equal to max, decrypt equal to input.
- RSA-4096 and RSA-2048 PKCS#1 v1.5 signatures: qemu64 equal to max, verify OK.
- ECDSA P-256 cross-verify (`cov2-ecdsa-sequential.txt`): qemu64 sign verified by max and qemu64; max sign verified by qemu64.

Note on the ECDSA step: the first cross-check batch ran in parallel with an earlier batch that regenerated the test key, so its ECDSA verify
lines failed. The step was re-run sequentially with a fresh key (`ec2.pem`), and all four verifies passed. The failed lines are not used.
