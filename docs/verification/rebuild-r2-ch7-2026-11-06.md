## 4. ISA audit after chapter 7 (`audit-isa.sh`, exit 0)

Scanned `usr/lib`, `usr/lib32`, `usr/bin`, `usr/sbin`: 1082 ELF files. Log:
`scratch-lfs-bench/lfs13-logs/audit/ch7-audit-20261106.txt`. Result: `audit: 1082 file(s) scanned, 0 with nonvariant AVX/BMI hits (2916 hit(s) allowlisted, 0 unallowed)`, exit 0.

The first run of the ch7 tree failed on two files, `usr/lib/python3.14/lib-dynload/_blake2.cpython-314-x86_64-linux-gnu.so`
and `_hmac.cpython-314-x86_64-linux-gnu.so` (1444 hits each). Both contain CPython's HACL\* Blake2b AVX2 path
(`_Py_LibHacl_Hacl_Hash_Blake2b_Simd256_*`). Checked before allowlisting:

- `blake2module.c` (CPython 3.14.7, Modules/): `type_to_impl` returns `Blake2b_256` only when `has_simd256()` is true, and that
  flag comes from `detect_cpu_features()` (CPUID leaf 1 AVX and leaf 7 AVX2 bits). Otherwise the portable `Blake2b` is used.
- `hmacmodule.c`: `can_run_simd256` is set from the same CPUID bits (`avx && avx2`, with SSE family as well), and the
  SIMD paths are taken only when it is set.
- Disassembly: the two static helper copies that contain VEX code (`update_block`, `malloc_raw`) have only Simd256 or
  VEX callers (checked per copy: `update_block` 8 callers, `malloc_raw` 3 callers).
- Limit: CPython checks CPUID bits, not XGETBV (OS support for YMM state). This is CPython's design; it is not changed here.

These six allowlist lines are in `scripts/lfs-blfs/cpu-baseline/audit-isa.allow` (commit of the audit tool, see BACKLOG). The
qemu64 gate (no AVX) takes the portable path.
