# REBUILD-R3: base packages recorded through alp (2026-11-07)

Status: **Partial**. 93 of 94 packages have an alp record. The 94th (systemd) is refused by alp
because one of its files has a backslash in its name, and the ownership check against alp's own
records fails with 2273 unowned files, all of them systemd files. Decision needed (section 8).

## 1. Method

Decision quotes:
- D141 (docs/DECISIONS.md): "During the rebuild every base package is installed through `alp`,
  so the file-ownership ledger is created automatically. This closes the v1 D34 debt."
- D122: "Package engine: `alp`."

What was done (the method the coordinator chose, per D141):
1. `r3-root` = writable btrfs copy of `scratch-lfs-bench/lfs13-snapshots/after-ch7-2026-11-06`
   (the state before ch8). `before-r3-2026-11-07` (read-only) was taken before any change.
   `/mnt/lfs13` was not changed and was only read (dry-run compare).
2. Each chroot step was run on `r3-root` with `scripts/rebuild/run-chroot.sh` (R3 options:
   `R3_ROOT`, `R3_LOGROOT`, `R3_SKIP_TESTS`, `R3_TEST_KEEP`, `R3_BODY_FILE`). Before and after each
   step a read-only snapshot was taken and `r3_ledger.py diff` listed the added, changed and
   deleted files and symlinks (ctime, size, mode, owner, symlink target). One snapshot was kept at a
   time, so pre-N is the post-(N-1) snapshot.
3. Owner of a path = the last step that wrote it (`r3_ledger.py owners`). A later delete releases it.
4. Manifests (`alp` format `alpbahOS.package-files/v1`) were generated from the final state of
   `r3-root`, after all steps (`r3_ledger.py manifests`). Each manifest is adopted with
   `alp adopt-base` (`--source-sha256`, `--manifest-sha256`).
5. The alp prototype (`docs/handoffs/claude/alp-prototype/alp.py`) was installed into `r3-root` at
   `/usr/lib/alp/alp.py` with `/usr/bin/alp`, as its own step `zz-alp`.

Test steps: the test targets were skipped (`R3_SKIP_TESTS=1`, shim `scripts/rebuild/r3/test-skip-shim.sh`)
except for the scripts whose own gates count test results: `03-glibc`, `20-binutils`, `21-gmp`,
`22-mpfr` (ch08-31b only), `31-gcc`, `53-python`, `73-vim`. Those ran their tests.

## 2. Deviations from the plan, and why

- **ch08-00 (glibc lib32 conf) is not run.** Its header says "Not part of the 01-82 order" (a repair
  step for an existing root); `03-glibc.sh` contains the same step.
- **MPFR (ch08-22): the test gate is deferred.** Its gate needs 198 PASS, 0 SKIP, 0 FAIL, but the
  chapter 6 libgcc has no BID objects until GCC is rebuilt (R2 note CH6-LIBGCC-BID). So ch08-22 builds
  and installs MPFR with the test step removed (`scripts/rebuild/r3/22-mpfr-notest.sh`, derived from
  `ch8/22-mpfr.sh` by deleting its gate, lines 25-38). **The test gate was deferred, not passed, at
  ch08-22.** The test was run after GCC in step **ch08-31b** (same script, full gate):
  `mpfr: '# PASS' total=198, '# SKIP' total=0, '# FAIL'+'# ERROR' total=0`, log
  `scratch-lfs-bench/lfs13-logs/r3/ch8/22-mpfr.log` (mpfr 4.2.2 rebuilt in place). MPC was not
  rebuilt: `libmpfr.so.6` keeps its SONAME and the file is byte-identical to the R2 tree
  (sha256 `40ce8ac66ab00be33903...`).
- **The out-of-book tarballs** (cpio 2.15, dracut-ng 112) are not in the book md5sums. Their sha256
  is recorded in R2 (`docs/verification/rebuild-r2-ch9-ch10-2026-11-07.md`); the ledger accepts a
  local tarball only when its sha256 starts with the recorded 20-digit prefix. No upstream signature
  was checked (same as R2).
- **Host-staged inputs** that R2 had staged in `/mnt/lfs13/sources` were copied (not built) into
  `r3-root/sources`: `config-fedora-7.2.7-200.fc44` (sha256 matches the script's pinned value),
  `cpio-2.15.tar.bz2`, `dracut-ng-112.tar.gz`, `kvm-emulate-host-avx-gate.patch`. `/sources` is outside
  the base, so these copies add no owned files.
- **Chapter 5-7 leftovers.** 2644 files of the after-ch7 tree were not written by any chapter 8+ step
  (`usr/lib/perl5` 1596, `usr/include/linux` 805, other kernel header directories 221, and `bin`
  as a symlink). They are not toolchain-only (no `/tools` directory exists in this root). They are
  recorded as one explicit pseudo package, `alpbahos-ch05-07-leftover`, whose source identity is the
  sha256 of the exact path list (`r3-steps/ch05-07-leftover.tsv`). **This is not a per-package record**:
  these files belong to the chapter 6 packages, and attributing them correctly is an open item.
- **ch08-22 and ch08-31b both write MPFR.** Owners are grouped by package name, so MPFR is one
  package with one owner per path. The paths written by both steps are counted in the conflicts file
  as "written by more than one step" but are not conflicts between packages.

## 4. The refused package (blocker)

`alp adopt-base` refuses the systemd manifest with
`Geçersiz taban manifest yolu: '/usr/lib/systemd/system/system-systemd\x2dmute\x2dconsole.slice'`.
The file name contains backslashes. It is a real systemd escaped unit file. `_base_manifest_relpath`
in `alp.py` rejects any backslash on purpose. Only this one path in the tree has a backslash.

This is a design decision, so it was not changed here. Options:
- (a) Allow backslashes in base manifest paths (a POSIX file name; the other checks such as no
  `..`, no empty parts and no `var/lib/alp` stay). Requires an alp change and a test. Recommended.
- (b) Drop that one path from the systemd manifest and document it as an exception. The file stays
  unowned unless it is added to the exclusion list, which weakens "no unowned base files".
