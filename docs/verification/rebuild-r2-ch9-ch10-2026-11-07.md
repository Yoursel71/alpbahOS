## 4. Kernel configuration (01-kernel-config)

Method: start from the Fedora 44 kernel config of the build host.

- Base: `/boot/config-7.2.7-200.fc44.x86_64`, copied to `/mnt/lfs13/sources/config-fedora-7.2.7-200.fc44`, sha256 `4c8b7e6d12f317c48701c8424dd2c1c0855ff85b1872840fe7bec7a90926adbc`. The script checks this hash before use.
- Then `make olddefconfig` for linux-7.1.8, then `scripts/config` edits and checks (`scripts/rebuild/ch10/01-kernel-config.sh`).
- Result config: `scripts/rebuild/ch10/kernel-7.1.8.config` (12304 lines, sha256 `38a4b4291ad0b99632d2...`, identical to the build-root copy).

Forced options and their final state:

- `LOCALVERSION="-alpbahos"`, so the release is `7.1.8-alpbahos` (checked by `make -s kernelrelease`).
- `RUST` off (Fedora enables it; the chroot has no rustc).
- `DEBUG_INFO_BTF` and `DEBUG_INFO_BTF_MODULES` off (no pahole).
- `X86_NATIVE_CPU` off.
- `MODULE_SIG_KEY=""`, `SYSTEM_TRUSTED_KEYS=""`, `MODULE_SIG_ALL` off.
- `SYSTEM_REVOCATION_LIST` off. There is no `SYSTEM_REVOCATION_KEYS` symbol in 7.1.8; the request's name does not exist in this tree.
- **Deviation: `MODULE_SIG` stays `y`.** `security/lockdown/Kconfig:4` selects `MODULE_SIG` when `SECURITY_LOCKDOWN_LSM` is on, and the Fedora config enables lockdown. Consequences: no signing key, no signing at `modules_install`, `MODULE_SIG_FORCE` off, so unsigned modules load. Lockdown itself stays on.
- **Deviation: no `x86-64` processor-family option.** In this tree the `X86_GENERIC` and processor-family choice is under `X86_32` (`arch/x86/Kconfig.cpu:3`, `:237`). For x86-64 the generic flags come from `arch/x86/Makefile:171` (`-march=x86-64 -mtune=generic`), and the script checks that line. The check of the flags in the compiled objects is not done: the build did not use `V=1`, so the log has no compile flags. Unverified.
- No CPU-specific `config M...` option from `arch/x86/Kconfig.cpu` is on (checked against the names in the tree).
- systemd options (systemd 261.2 README, Kernel section): DEVTMPFS, DEVTMPFS_MOUNT, CGROUPS, INOTIFY_USER, SIGNALFD, TIMERFD, EPOLL, UNIX, SYSFS, PROC_FS, FHANDLE, SYSFS_DEPRECATED off, UEVENT_HELPER_PATH empty, FW_LOADER_USER_HELPER off, DMIID, DMI, DMI_SYSFS, BLK_DEV_BSG, NET_NS, USER_NS, IPV6, AUTOFS_FS, TMPFS_XATTR, TMPFS_POSIX_ACL, EXT4 and BTRFS POSIX ACL, SECCOMP, SECCOMP_FILTER, KCMP. Book notes: PCI_MSI, IRQ_REMAP, X86_X2APIC, DRM on.
- Storage: EXT4_FS=y, BTRFS_FS=y, VIRTIO_BLK=y, VFAT_FS=y, EFI_PARTITION=y; NVME_CORE=m, BLK_DEV_NVME=m, SATA_AHCI=m, SCSI_VIRTIO=m, DM_CRYPT=m.

Three failed attempts before the final run, all fixed in the script and recorded here: (1) `RUST` and the `SYSTEM_REVOCATION_KEYS` name did not match the 7.1.8 tree, and `MODULE_SIG` was re-enabled by lockdown; (2) the `GENERIC_CPU` symbol does not exist for x86-64 (section 4 above).

## 5. Kernel build (02-kernel-build) and cpio (03-cpio)

- `02-kernel-build`: `make -j16`, 1936 s, rc=0. `make modules_install` into `/lib/modules/7.1.8-alpbahos`. Copied to `/boot`: `vmlinuz-7.1.8-alpbahos` (16806400 bytes), `System.map-7.1.8-alpbahos`, `config-7.1.8-alpbahos`. The `/boot/vmlinuz-7.1.8-alpbahos` is a bzImage, not an ELF file, so the ISA audit does not read it as code.
- The book's `make menuconfig` is replaced by the scripted config (section 4).
- **cpio 2.15** is not in the MLFS 13.1 book (it is a BLFS package), and the chroot had no cpio, which dracut needs. Source `cpio-2.15.tar.bz2` (1651320 bytes) from `https://ftp.gnu.org/gnu/cpio/`, sha256 `937610b97c329a1ec926...`. The GNU signature was not checked.
- First build failed (rc=2): GCC 15 defaults to C23, where an empty `()` declaration means `(void)`, and cpio 2.15's gnulib code then fails (`too many arguments to function 'xstat'`). Fix: `CFLAGS="-O2 -std=gnu17" ./configure ...`. No CPU flags. Re-run rc=0, `cpio (GNU cpio) 2.15`.

## 6. dracut and initramfs (04-dracut, 05-initramfs)

- **dracut-ng 112** is the version the M11 work used (`M09 build-parameter.txt` records it). Source `dracut-ng-112.tar.gz` (601803 bytes) from `https://github.com/dracut-ng/dracut-ng/archive/refs/tags/112.tar.gz`, sha256 `839d21eb4bd27bb0ee40...`. It is outside the LFS book, and no signature was checked. Built with `./configure --prefix=/usr --sysconfdir=/etc --disable-documentation`. Result `dracut 112`.
- **Deviation from the M11 options**: M11 used `--no-hostonly --no-kernel --add alplive --omit ...` for the live ISO. Here `--no-kernel` is dropped, because this kernel is modular and the modules must go into the initramfs; `--add alplive` is dropped (live-only).
- The omit list is the M11 list minus `systemd` and `systemd-udevd`, so the udev daemon and rules stay in the initrd and `/dev/disk/by-uuid` can be created for `root=UUID=`. The M11 list did not include `udev-rules`; it is not omitted here either.
- Command: `dracut --force --no-hostonly --kver 7.1.8-alpbahos --add-drivers dm_crypt --omit 'dracut-systemd systemd-initrd systemd-journald systemd-sysusers systemd-tmpfiles systemd-hwdb systemd-networkd systemd-battery-check' /boot/initrd.img-7.1.8`.
- First build had no `dm_crypt`: dracut's crypt module is not loaded by default. Fixed by `--add-drivers dm_crypt`; the initrd now contains `usr/lib/modules/7.1.8-alpbahos/kernel/drivers/md/dm-crypt.ko`.
- Contents, from `lsinitrd` (short): 2008 entries; `init`, `rootfs-block`, `usr/lib/systemd/systemd-udevd` (a symlink to `udevadm`), `nvme-core.ko`, `ahci.ko`, `dm-crypt.ko`. ext4 and btrfs are built in (`CONFIG_EXT4_FS=y`, `CONFIG_BTRFS_FS=y`), so no ext4 or btrfs module is in the initrd.
- **Not boot-tested.** The initrd has not run in a VM or on hardware. That is the next phase.
- Mode of `/boot/initrd.img-7.1.8` is 0600 (dracut default); not changed.

## 8. ISA audit

Tool: `scripts/lfs-blfs/cpu-baseline/audit-isa.sh`, run on the host with the default allowlist `audit-isa.allow`. The audit's `find` picks only `*.so*` and executable files (`audit-isa.sh:88`), so kernel modules (`*.ko`) are NOT scanned by the directory run. The first run therefore did not cover the new modules, and a second run was made on the modules explicitly.

**Run A, whole tree except modules** (`/mnt/lfs13/usr/lib /mnt/lfs13/usr/lib32 /mnt/lfs13/usr/bin /mnt/lfs13/usr/sbin /mnt/lfs13/boot`), log `scratch-lfs-bench/lfs13-logs/isa-ch10/audit.out`:

```
audit: 2487 file(s) scanned, 0 with nonvariant AVX/BMI hits (10867 hit(s) allowlisted, 0 unallowed)
AUDIT_RC=0
```

The allowlisted count 10867 is the same as the ch8 close-out line (`docs/verification/rebuild-r2-ch8-2026-11-06.md:250`), and 2487 - 2482 = 5 new ELF files (the cpio and dracut binaries and the new systemd symlink). No new hits outside modules.

**Run B, kernel modules** (4990 `.ko` files under `/mnt/lfs13/usr/lib/modules/7.1.8-alpbahos`, passed as file arguments), log `isa-ch10/audit-ko.out`:

```
audit: 4990 file(s) scanned, 12 with nonvariant AVX/BMI hits (0 hit(s) allowlisted, 15869 unallowed)
AUDIT_RC=1
```

Nonvariant hits: 12 modules have nonvariant hits, with 48 NONVARIANT lines (distinct function names) in total. Per module, from the `audit-ko.out` per-file summary:

| Module (under kernel/) | Nonvariant hits |
|---|---|
| arch/x86/crypto/serpent-avx2.ko | 6538 |
| arch/x86/crypto/cast6-avx-x86_64.ko | 2288 |
| arch/x86/crypto/camellia-aesni-avx2.ko | 1995 |
| arch/x86/crypto/camellia-aesni-avx-x86_64.ko | 1937 |
| arch/x86/crypto/twofish-avx-x86_64.ko | 1499 |
| arch/x86/crypto/cast5-avx-x86_64.ko | 1448 |
| arch/x86/kvm/kvm.ko | 32 |
| arch/x86/kvm/kvm-amd.ko | 6 |
| (4 other modules, 126 hits together) | |

The 8 rows above sum to 15743. The other 4 modules account for the remaining 126 of 15869; their names are in `isa-ch10/audit-ko.out` (grep `NONVARIANT`). Function names were not reviewed one by one in this phase.

Decision: **left OPEN.** The coordinator's rule is that allowlisting needs kernel gate evidence per exact symbol (`boot_cpu_has` / `cpu_feature_enabled` at file:line). 48 symbols across 12 modules is too many to review with that evidence in this phase, so nothing was allowlisted and the module audit is not forced to RC=0. The modules are the kernel's runtime-dispatched crypto (AVX/AVX2 selected at module init from the CPU features) and KVM's SVM path; those are expected, but unverified per symbol. Next step: review the module init gates per module, then add exact-symbol entries.

**Update 2026-11-07 (CPU-BASELINE-03):** all 12 modules are now allowlisted with gate evidence (48 exact-symbol entries in total: 46 from the first pass plus 2 for kvm.ko, reviewer haiku-agent/2026-11-07). `kvm.ko` needed a local host-AVX gate in `emulate.c` (patch `scripts/rebuild/ch10/patches/kvm-emulate-host-avx-gate.patch`, applied by `02-kernel-build.sh`). The module run is now RC=0 and the main-tree run RC=0. Details: [cpu-baseline-03 note](cpu-baseline-03-kernel-modules-2026-11-07.md).

Audit line for the record: `audit: 4990 file(s) scanned, 12 with nonvariant AVX/BMI hits (0 hit(s) allowlisted, 15869 unallowed)`, exit code 1.
