# M04 LFS source archive verification

The ordered Chapter 8 inventory is tracked in
[`m04-lfs-12.4-package-coverage-2026-09-24.md`](m04-lfs-12.4-package-coverage-2026-09-24.md).
The pinned machine-readable source list is
[`m04-lfs-12.4-systemd-ch8-source-md5.json`](m04-lfs-12.4-systemd-ch8-source-md5.json).
It contains the 79 Chapter 8 package archives in that table's order. The
official LFS checksum index snapshot is
[`m04-lfs-12.4-systemd-official-md5sums.txt`](m04-lfs-12.4-systemd-official-md5sums.txt).

The snapshot was retrieved on 2026-09-24 from the official
[LFS 12.4-systemd md5sums file](https://www.linuxfromscratch.org/lfs/downloads/12.4-systemd/md5sums).
Its SHA-256 is `d18a55ca1aa4eb0f483f134cd44287ea8d48eeb1def5fa0c8d07fe44f38dbb17`.
The verifier checks this snapshot hash, checks every pinned MD5 against the
snapshot, and checks that package labels still follow rows 1–79 of the
coverage table.

Run the read-only verifier on Builder, where the archives are stored, from a
checkout containing the verifier and its pinned data files:

```bash
python3 /path/to/alpbahOS/scripts/verify-lfs-ch8-sources.py --source-dir /mnt/lfs/sources
```

It searches recursively through real directories for each expected archive
basename and writes one JSON object per expected package, followed by a summary
object. Successful hashes include both the official MD5 comparison and the
actual SHA-256. Missing files, duplicate basenames, non-regular matching paths,
read errors, detected file changes, or checksum mismatches produce a nonzero
exit status. Unrelated cache files are ignored. Symlink directories are not
followed and are reported as scan errors. The source tree must remain trusted
and quiescent for the entire recursive scan and verification. Descriptor-based
hashing refuses a final-component symlink where the operating system supports
`O_NOFOLLOW`, rejects non-regular opened objects before reading, and compares
path/descriptor identity before and after hashing; it does not make recursive
directory traversal atomic against a hostile concurrent writer. The source
directory is only read; the verifier creates no files there.

The CLI intentionally accepts only the committed manifest, package coverage
table, and official checksum snapshot. It has no manifest or coverage override;
the internal loader's optional coverage argument exists for isolated tests.

The expected values are the MD5 checksums published by LFS. They verify that an
archive matches the book's listed identity; MD5 is not a modern authenticity
mechanism. Check current LFS security advisories before using an older book
release for a build.

Focused tests:

```bash
python -m unittest tests.test_m04_lfs_ch8_source_verifier -v
```
