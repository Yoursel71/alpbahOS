## 4. KUTU: where the fix belongs (not changed here)

netavark fixed the network part of handoff 038. What still stops the box is the locale spelling the installer
writes. Calamares writes `tr_TR.utf8` (the `locale -a` spelling); r4-root has no `/etc/locale.gen` for its locale
module to read. distrobox 1.8.2.5's Debian/Ubuntu path (`distrobox-init` lines 858-867) matches the host locale
case-sensitively against Debian's `locale.gen`. Possible fixes, for the owner of the installer / DISTROBOX-01:

1. Make the installed system say `tr_TR.UTF-8`, e.g. give the Calamares locale module a `localeGenPath` file that
   lists `tr_TR.UTF-8 UTF-8`. The KUTU-locale row shows that this one change is enough for the whole KUTU flow.
2. Or patch `distrobox-init` (case-insensitive match and a normalised name for `update-locale`). This also covers
   systems already installed with `tr_TR.utf8`.

alp itself needs no change for this. Its kutu path works once the box can be set up.
