# M11 — D144 PARTUUID boot via the product grubcfg path (2026-11-06)

Decision: D144 (installed system boots with `root=PARTUUID=…`, no initramfs). Closes OPEN-1.

## Environment
- Host: Fedora, QEMU/KVM. LFS 12.4 chroot `/mnt/lfs` mounted with `scripts/lfs-blfs/mount_lfs.sh`.
- Host module `squashfs` loaded with `sudo modprobe squashfs` before the run (the runner now refuses to start without it).
- Target: a NEW sparse 20 GiB image file `scratch-lfs-bench/m11-runner/m11-target-d144-20261106.img`. No real disk was written.

## What changed before the run
- `scripts/lfs-blfs/calamares/modules/grubcfg.conf` (new): `overwrite: true`; defaults `GRUB_DISTRIBUTOR: "alpbahOS"`, `GRUB_DISABLE_LINUX_UUID: true`, `GRUB_DISABLE_LINUX_PARTUUID: false`, `GRUB_DISABLE_RECOVERY: true`, `GRUB_TIMEOUT: 5`.
- `scripts/lfs-blfs/calamares/modules/bootloader.conf` (new, from the chroot copy): `kernelSearchPath: "/boot"`.
- `grubcfg` added before `bootloader` in both `settings.conf` files.
- `runner/m11-run.sh`: copies the two repo module configs; hard-fails without squashfs; checks `/usr/bin/bash`, `/etc`, `/boot` in the target after unpackfs; checks the grubcfg output. The old test-only `GRUB_DEVICE='PARTUUID=…'` line now runs only with `M11_GRUB_DEVICE_OVERRIDE=1`; this run did NOT set it, so the product path alone was tested.
