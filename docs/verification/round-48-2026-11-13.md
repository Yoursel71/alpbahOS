## A scripting mistake, caught and fixed

`scripts/rebuild/r48/r48-run.sh` initially called `run-r25.sh b2`, which is not a valid subcommand (B2 is a `diag`
row in `matrix-r21.sh`, called as `matrix-r21.sh diag B2`). It failed silently (no error surfaced in `run.log`,
just an instant "done: b2" with no real test run). Caught by checking the row's actual output, not just its log
line; the script source is now fixed for future rounds. Lesson: a round script copied from a previous round's
pattern needs its row invocations checked against the actual subcommand list, not assumed.

## A real incident during ISO-size cleanup (separate from the test matrix)

While investigating the user's request to shrink the ISO, stripping debug symbols from r4-root's own live, mutable
root (not a snapshot) corrupted `usr/lib/libc.so.6` (truncated to 0 bytes) through a race between the chroot strip
loop and concurrent verification scans against the same live file. Recovered immediately from the
`lfs13-snapshots/r4-iso-src-2026-11-09-prev-r47` snapshot; r4-root verified healthy afterwards (`ldconfig -v`,
`python3`, `bash`, `strip`, `alp` all run clean). ~1628 of 5517 unstripped files were safely stripped before the
race; the remaining 3889 were left alone. Full account in
`docs/handoffs/claude/044-nvidia-real-pc-r48-plan-2026-11-13.md`.

Not run on real hardware. Open after this round: `lpinfo dnssd` root cause still needs a two-host check; NVIDIA
real-GPU proof still needs the user's supervised VFIO session or a real-PC USB boot (D179, D180); ISO size
reduction (locale/doc/static-lib trimming) still not attempted, given the strip incident above.
