# Round 48p: PRINT-02 with the printer on a second machine, 2026-11-13

ISO `alpbahos-beta-0.9-2026-11-09-r48.iso` (sha256 `1ed96f37...`, as in [round 48](round-48-2026-11-13.md)). Script
`scripts/rebuild/r48/print2-r48.sh`: two reflink copies of the round 48 UEFI install share a private LAN (QEMU socket
netdev on a multicast group, static 10.77.0.1/.2 plus IPv6 link-local, each keeps its user-mode NIC). P2A runs CUPS'
`ippeveprinter` as the network printer (hostname set to `alpbah-printer`, tcp/8631 opened in its firewall for the
test); P2B is an unchanged alpbahOS install acting as the user's machine. Evidence
`scratch-lfs-bench/lfs13-logs/iso-beta-0.9/r48p/matrix/` (the third run; `matrix-try1/`, `matrix-try2/` are the
earlier runs). Not a real printer, not a real LAN.

| Check on P2B (the user's machine) | Result |
|---|---|
| Services | avahi-daemon, cups, cups-browsed, alpbahos-firewall active; nothing changed in P2B's firewall |
| `avahi-browse -rt _ipp._tcp` | PASS: "alpbah LAN Printer" over IPv4 (10.77.0.1) and IPv6 link-local |
| `ippfind` | PASS: `ipp://alpbah-printer.local:8631/ipp/print` |
| nss-mdns | PASS: `alpbah-printer.local` resolves to 10.77.0.1 |
| `lpinfo --include-schemes dnssd -v` | lists the printer (empty in every one-guest PRINT row). On P2A, the printer's own host, the same command is empty: CUPS' dnssd backend skips services of its own host, as handoff 044 guessed, so the empty one-guest result was the test setup, not alpbahOS |
| Print dialogs (`lpstat -e`, CUPS temporary queues) | PASS: `alpbah_LAN_Printer` (`ipps://...`) appears with no setup, and a PDF sent to it with `lp` completed and reached the printer |
| Queue added by hand (`lpadmin -m everywhere`, IPP URI) | PASS: 1 job completed, received by the printer |
| cups-browsed | creates no permanent queue (`lpstat -v` empty after 90 s); `cups-browsed.conf` has only `BrowseRemoteProtocols dnssd`. Not needed for printing since the temporary queue above works; left as it is |
| Failed units | `NetworkManager-wait-online` on both guests: the second NIC has no DHCP server on the test LAN, so the boot-time wait times out (every one-NIC row has 0 failed units). Test setup |

Open, minor: `lpinfo` gives the URI `dnssd://alpbah%20LAN%20Printer._printer._tcp.local/` (the LPD record, which
`ippeveprinter` publishes with port 0); a queue made from that URI tried port 515 and failed in the first run. A real
printer publishes its own records, so whether the KDE "add printer" page picks an IPP URI needs a real printer on a
real LAN. The run's first try also showed that two machines with the same hostname (`alpbahos-test`, the test
images' name) confuse `.local` names; installs get the hostname the user types, so this is the test images.

PRINT-02 status: discovery and printing to a network printer on another machine work in the VM; the remaining check
is a real printer.
