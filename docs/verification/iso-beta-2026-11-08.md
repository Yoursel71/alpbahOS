# AlpbahOS BETA live ISO and Calamares installer (2026-11-08)

Status: **release candidate, install tested on UEFI and BIOS.** The live ISO boots on BIOS and UEFI to the Plasma
desktop. The Calamares install completes on UEFI and on BIOS (30 GiB image files), and both installed images boot to
the Plasma desktop after login. Known limitations are in section 5.

Host: `thewo`, worktree `/home/yrslf/alpbahOS/wt-t2-kisayol`, branch `claude/t2-kisayol-2026-11-05`.
Data in `scratch-lfs-bench/` (not in the repo). Heavy work ran under `nice -n 19 ionice -c3`.
No real disk, host `/boot`, NVRAM or `/mnt/lfs` was written. Install targets are image files attached to QEMU;
the installed images were inspected read-only through loop devices.

- ISO: `scratch-lfs-bench/images/alpbahos-beta-2026-11-08.iso`, 4714862592 bytes (4.4 GiB)

## 5. Deviations and open items

Deviations (all recorded when they were made):

- **D-1 Non-book sources.** yaml-cpp 0.9.0, kpmcore 26.08.3 and Calamares 3.3.14 are GitHub tags, not in BLFS 13.1.
  sha256 is trust-on-first-use: yaml-cpp `25cb0432...efd49`, kpmcore `617aa4ba...be3bc1`, Calamares `fa158d67...5dad4a`.
- **D-2 parted without device-mapper** (`--disable-device-mapper` at row 363, before lvm2 existed). LVM and dm-crypt
  partitions are not visible to the installer. Plain GPT and MBR disks are fine.
- **D-3 libaio source.** The book URL returns 404. The file is the Debian mirror's `libaio_0.3.113.orig.tar.gz`, with
  the book's md5 `7d5be185...`.
- **D-4 lvm2 added** (row 371) for `dmsetup`, needed by dracut's `dm` module for `dmsquash-live`.
- **D-5 Partitioning.** UEFI installs use GPT with an EFI partition; BIOS installs use MSDOS with one root partition.
- **D-6 Test-only items still in the release candidate (remove before a public release).**
  - `/etc/profile.d/99-alpbahos-live.sh` sets `LIBGL_ALWAYS_SOFTWARE=1`. Kept because the QEMU virtio GPU has no
    virgl; not tested without it. The installed system does not have the file.
  - Live user password `live`, and the sddm autologin keys in `/etc/sddm.conf`.
  - No debug arguments and no installer log on the serial port in the release candidate.
- **D-7 Installed initramfs.** Generated by dracut in the target (generic, no hostonly, shell init). It makes the
  installed kernel independent of AHCI/NVMe being built in. Verified only with virtio disks in QEMU; the AHCI and NVMe
  modules were not checked in the image, and no real hardware was tested.
- **D-8 Installer runs as root through pkexec** with a polkit rule for user `live`. R4 has no sudo.
- **D-9 Accelerator.** (a) and (b) ran under TCG (`-cpu qemu64`). (c) ran under KVM with the same CPU model.
- **D-10 Installed system uses the systemd init** (dracut's shell init in the initramfs, then systemd).

Open items:

1. UEFI autologin: repeatable? (one passing run on the RC and one on the debug build; earlier runs failed).
2. Remove or justify `LIBGL_ALWAYS_SOFTWARE=1` (test without it).
3. Rebuild parted with device-mapper now that lvm2 exists (D-2).
4. Check AHCI and NVMe modules inside the installed initramfs (D-7); test on real hardware is outside this run.
5. Disk: `/home` had about 24 GiB free after the test images. The two installed test images are 18 GiB each on disk
   (`alpbahos-beta-install-uefi.raw`, `alpbahos-beta-install-bios.raw`, both 30 GiB virtual). Delete them after review.
