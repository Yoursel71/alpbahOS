## 2. Deviations (must be resolved or accepted before release)

- **D-1 Non-book sources.** yaml-cpp, kpmcore and Calamares are not in BLFS 13.1. They come from GitHub
  release tags. sha256 values are recorded trust-on-first-use: yaml-cpp `25cb0432...efd49`, kpmcore
  `617aa4ba...be3bc1`, Calamares `fa158d67...5dad4a`. These match the M11 records (2026-11-05).
- **D-2 parted without device-mapper.** `--disable-device-mapper` because lvm2 was not in R4 at row 363.
  Plain GPT and MBR disks are unaffected. LVM and dm-crypt partitions are not visible to the installer.
  Open: rebuild parted now that lvm2 (row 371) exists.
- **D-3 libaio source.** The book's `releases.pagure.org` URL returns 404. The file is the Debian
  mirror's `libaio_0.3.113.orig.tar.gz`, with the book's md5 `7d5be185...`.
- **D-4 lvm2 added.** dracut's `dmsquash-live` needs the `dm` module, which needs `dmsetup`. R4 had none.
  Row 371 provides it. Not a Calamares dependency.
- **D-5 Calamares partition backend.** The GPT/EFI layout is used on UEFI. BIOS installs were not run.
- **D-6 Test-only settings in the live image (remove before release).**
  - `/etc/profile.d/99-alpbahos-live.sh` sets `LIBGL_ALWAYS_SOFTWARE=1` (QEMU virtio GPU has no virgl).
  - Live user password `live`, and sddm autologin keys in `/etc/sddm.conf`.
  - Kernel arguments `rd.debug systemd.journald.forward_to_console=1` (diagnostic, build 5 onward).
  All of these are removed from the installed system by `target-cleanup.sh`, except the kernel arguments
  (they are on the ISO only).
- **D-7 No initramfs in the installed system (D144).** The installed kernel has `SATA_AHCI=m` and
  `NVME=m`. A real AHCI or NVMe disk will not boot without an initramfs. Only virtio disks boot in QEMU.
- **D-8 Installer runs as root through pkexec** with a polkit rule for user `live`. There is no sudo in R4.
  Calamares `users` has `sudoersGroup: ""` (see the failure in section 3c).
- **D-9 Accelerator.** (a) and (b) ran under TCG (`-cpu qemu64`). (c) ran under KVM with the same CPU model
  (`ACCEL=kvm`), because TCG was too slow for the unpack on this host.

### 3c. Calamares install onto a blank 30 GiB raw image (UEFI): FAIL (not completed)

Target `scratch-lfs-bench/images/alpbahos-beta-install-uefi.raw` (sparse, 30 GiB virtual). Attempts:

1. Launcher ran but Calamares did not start. Debug output (run from Konsole with `alpbahos-install -d`) showed
   `Failed to initialize KPMcore backend`. The pkexec environment dropped `QT_PLUGIN_PATH`. Fixed in the
   wrapper (`QT_PLUGIN_PATH=/usr/lib/plugins:/opt/qt6/plugins`, `QML2_IMPORT_PATH`).
2. Installation failed in the `users` job: `sudoers dosyası oluşturulamadı ve yazılamadı` (could not create the
   sudoers file). Cause: `sudoersGroup: wheel`, but R4 has no sudo, so `/etc/sudoers.d` does not exist. Fixed:
   `sudoersGroup: ""`. Evidence: Konsole screenshot `scratchpad/dbg12-50.png` (not in the repo) and the log lines
   quoted here.
3. Installation with the fixed ISO (build 6) ran to 37% and then stopped without an error dialog. The screen went
   to the lock screen and then to "Display output is not active". State read from the target disk (loop device,
   read-only):
   - `/etc/fstab` written by Calamares (UUIDs present). `testuser` created in `/etc/passwd`.
   - EFI partition empty. Bootloader step did not run.
   - `/home/live`, `/etc/calamares` and the live profile script still present. Autologin keys not reset.
   - `/boot/grub/grub.cfg` still has the template placeholder `root=UUID=@ROOT_UUID@`.
   So the failure is in the exec phase after `users` and before `shellprocess`. The Calamares log for that
   run was not captured, so the exact failing job is open.

Installed-system boots: **not run** (no completed install). Serial shows no login for the installed disk.
The "Display output is not active" screen on the installed disk is not explained. Likely the installed kernel
has virtio-gpu only as a module and no initramfs, so there is no framebuffer, and the installed grub entry has
no console. Not verified.
