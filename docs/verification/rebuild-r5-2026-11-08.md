## 7. Root cause of the kwin_wayland SIGSEGV (first attempt): not an ABI mismatch

- Backtrace (`kwin-backtrace.txt`): `QStyleHintsPrivate::update(QPlatformTheme const*)` <- `QGuiApplicationPrivate::handleThemeChanged`
  <- `QApplicationPrivate::handleThemeChanged` (Widgets) <- `QKdeThemePrivate::refresh` <- `QKdeTheme::createKdeTheme`
  <- `init_platform` <- `QGuiApplicationPrivate::createPlatformIntegration` <- `KWin::Application::Application`.
  Read at address 0. The built-in QKdeTheme (inside libQt6Gui) was used.
- Qt Gui, Widgets and the Wayland modules were all rebuilt at row 359 (11:36 to 12:04). The KDE platform theme plugin
  (`KDEPlasmaPlatformTheme6.so`, row 317, 10:08) is older. The hypothesis of a Qt private-ABI mismatch with older
  consumers was tested and is **not** supported: the crash is inside the new libQt6Gui, and the fix is a path setting.
- With `QT_PLUGIN_PATH=/usr/lib/plugins` the platform theme plugin is found, and kwin_wayland no longer crashes
  (run 4 and run 5: 0 kwin segfaults). So no consumer rebuild was needed for this crash.
- Checks that did not reproduce it: `kwin_wayland --virtual` in the R4 chroot (with a proper `XDG_RUNTIME_DIR`) runs
  for 30 s with `XDG_CURRENT_DESKTOP=KDE`. Earlier chroot results had no runtime dir and are invalid. Widgets apps
  (linguist, designer) offscreen with the KDE theme run without crashing. A QML app offscreen runs without crashing.
- Qt's `QT_PLUGIN_PATH`/`QML_IMPORT_PATH` for a `/opt/qt6` Qt is the real issue. The book's Qt 6 page for `/opt/qt6`
  is not checked here; the fix is recorded in R4 (section 3).
