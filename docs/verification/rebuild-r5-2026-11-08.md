| # | Symptom in the journal | Cause | R5 image fix (`r5-image-finish.sh`) |
|---|---|---|---|
| 1 | `sddm: Failed to start display server process`, `Running: /opt/xorg/bin/X` (BIOS run 1, UEFI run 1) | `/etc/sddm.conf` [X11] `ServerPath=/opt/xorg/bin/X`; the image has `/usr/bin/Xorg` only | `ServerPath=/usr/bin/Xorg` in the image copy of `/etc/sddm.conf` |
| 2 | `Authentication error ... "Permission denied"`, `Autologin failed!` (Plasma run 2) | `/etc/pam.d/system-login` and `system-local-login` do not exist; sddm and sddm-autologin include them, so the account stack falls back to `other` (`pam_deny`). The same gap breaks the normal sddm password login | both files added with the R4 `system-auth`, `system-account`, `system-password`, `system-session` stacks |
| 3 | no autologin attempt (Plasma run 1) | no autologin configured | `[Autologin] User=r5test`, `Session=plasma.desktop`, `Relogin=false` in `/etc/sddm.conf` |

Load-order note: sddm 0.21 (`src/common/ConfigReader.cpp`) reads `/usr/lib/sddm/sddm.conf.d`, then
`/etc/sddm.conf.d`, then the classic `/etc/sddm.conf`, and the last one has the highest priority. So the R4
values in `/etc/sddm.conf` override conf.d drop-ins. The first R5 attempts used drop-ins (`05-r5-xorg-serverpath.conf`,
`10-r5-test-autologin.conf`) and they had no effect; the script now edits `/etc/sddm.conf` and removes those drop-ins.

Test user: `r5test` (uid 1000, groups wheel, video, input, audio). The password is generated (`openssl rand -hex 12`)
and recorded in `configs/rebuild/r5-test-user.example.env` (repo example config, test image only). Note: the R4 root
also contains an account `RSTEST` that the sddm greeter lists; R5 did not create it.
