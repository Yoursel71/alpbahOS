## 3. R4 changes (recorded through alp in r4-root, not in git)

Each record is an alp package with the manifest in `r4-ledger/…`. Ownership of the files was moved from their earlier
records by `r4_lib.py transfer`.

| Record | Files | What and why |
|---|---|---|
| `sddm-config-r4fix` 13.1-r4fix | `etc/sddm.conf`, `etc/pam.d/sddm`, `etc/pam.d/sddm-autologin` | `ServerPath=/usr/bin/Xorg` (row 200 applied the book's `/opt/xorg` sed; Xorg is in `/usr`). `pam.d/sddm` as in the book's sddm page. `sddm-autologin` uses the `system-*` stacks (R4 has no `system-login` or `system-local-login`). |
| `qt6-kf6-paths-r4fix` 13.1-r4fix | `etc/profile`, `etc/profile.d/kf6.sh`, `etc/profile.d/qt6.sh` | See below. |

Profile setup (the book's method; BLFS 13.1 post-LFS profile page and KF6 intro page):
- `/etc/profile` had no `pathappend`/`pathprepend` and no `profile.d` loop, so `profile.d` was never read. The file now has the
  BLFS helper functions (`pathremove`, `pathprepend`, `pathappend`), the PATH setup, the locale block that was there, and the
  loop over `/etc/profile.d/*.sh`. The page's heredoc is not quoted verbatim here (copy restriction); the structure follows it.
- `/etc/profile.d/kf6.sh`: `export KF6_PREFIX=/usr` (the book's text for `/usr`).
- `/etc/profile.d/qt6.sh`: the book's KF6 extension for `/usr` (`pathappend /usr/lib/plugins QT_PLUGIN_PATH`,
  `pathappend $QT6DIR/plugins QT_PLUGIN_PATH`, `pathappend /usr/lib/qt6/qml QML2_IMPORT_PATH`, `pathappend $QT6DIR/qml QML2_IMPORT_PATH`).
  **Local addition:** `pathappend /usr/lib/qml QML2_IMPORT_PATH`. The KF6 and KDE QML modules of this build are in `/usr/lib/qml`
  (the book's KF6 install puts them in `/usr/lib/qt6/qml`).
- `/etc/environment` (the earlier attempt) is **removed**. The profile.d settings cover it. I checked the path with a login shell
  in the R4 chroot: `QT_PLUGIN_PATH=/usr/lib/plugins:/opt/qt6/plugins`, `QML2_IMPORT_PATH=/usr/lib/qt6/qml:/opt/qt6/qml:/usr/lib/qml`,
  `KF6_PREFIX=/usr`.
- Why it reaches the session: the sddm Wayland session script (`/usr/share/sddm/scripts/wayland-session`) runs the user's shell as a
  login shell for bash, which reads `/etc/profile`, which sources `profile.d`. `startplasma-wayland` then imports this environment
  into the systemd user manager, so the plasma user units inherit it. No `/etc/environment` line is needed for this.
- No ld.so.conf change: the book adds `/opt/kf6/lib` only for a `/opt/kf6` prefix. This build uses `/usr`.
- Leftover: the alp record `qt6-kf6-paths-r4fix-13.1-r4fix-leftover` still lists `etc/environment`, which is deleted on purpose.
  `alp check` passes (455 packages). The leftover record is bookkeeping only.
- `alp check` (R4 root, demo index): rc 0, 455 installed packages.

## 4. Image build and test-only finish

```
sudo btrfs subvolume snapshot -r $B/r4-root $B/lfs13-snapshots/r4-r5fix2-2026-11-08
sudo env R3_ROOT=$B/lfs13-snapshots/r4-r5fix2-2026-11-08 bash scripts/rebuild/image/build-image.sh $B/images/alpbahos-r5-2026-11-08.raw
sudo env R5_TEST_GL_SOFTWARE=1 R5_DEBUG_LIBPLASMA_DIR=$L/r5/libplasma-dbg bash scripts/rebuild/image/r5-image-finish.sh $B/images/alpbahos-r5-2026-11-08.raw
```

`r5-image-finish.sh` (new; loop device on the image only) does the test-only parts: test user `r5test` (uid 1000, wheel, video,
input, audio; password generated at run time by r5-image-finish.sh (see `configs/rebuild/r5-test-user.example.env`)), sddm `[Autologin]`
(`User=r5test`, `Session=plasma.desktop`), `LIBGL_ALWAYS_SOFTWARE=1` (the QEMU virtio GPU has no virgl; test only), no screen
lock and no DPMS or suspend for `r5test` (`kscreenlockerrc`, `powermanagementprofilesrc`; test only), and a RelWithDebInfo
`libPlasma.so.6.7.4` (same version, built from `libplasma-6.7.4.tar.xz` in the R4 chroot into a DESTDIR tree that is not installed in
R4; used only in the image). The Qt and KF6 paths are no longer set by the finish script.

Note: sddm 0.21 reads `/etc/sddm.conf` last, so its values win over `/etc/sddm.conf.d` drop-ins.
