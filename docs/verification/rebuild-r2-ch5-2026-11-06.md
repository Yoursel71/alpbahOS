## 4. Failure and fix

Failure (run 1, 04-glibc): the book's 5.5.2 (32-bit) `make` stopped on link errors in the `others`
targets (`debug/pcprofiledump`, `posix/getconf`): `undefined reference to printf / stdout / exit`.
`build/libc.so` was still being written at that time (its mtime equals the failing link's time).

Diagnosis: `build/config.log` has the book's 5.5.2 configure line. Running the same tree with
`make -j1` (no reconfigure, diagnostic `glibc-32-retry-make.sh` / `glibc-32-retry-make.log`) finished with
rc 0 in about 40 s. So the failure is a parallel-make race, not a toolchain problem.

Fix (`scripts/rebuild/ch5/04-glibc.sh`): the 32-bit `make` is now `make -j1`, with a comment. The rest of
the script is unchanged. Re-run 2 then passed the whole script from a clean `make clean`.

Note: `-j16` is kept for every other step. Only this step is serial.

## 5. ISA audit (`scripts/lfs-blfs/cpu-baseline/audit-isa.sh --report-only`)

Scanned: `/mnt/lfs13/usr/lib`, `usr/lib32`, `lib`, `lib32` (557 ELF files). Log:
`scratch-lfs-bench/lfs13-logs/audit/ch5-audit-20261106.txt`.

Result: 555 files clean. 2 files show nonvariant hits: `usr/lib/libm.so.6` (540) and
`usr/lib/libmvec.so.1` (693). The audit is name-based, so these are not yet proven OK by the tool.
Checked by hand (objdump, 2026-11-06):

- libm: the hits are static helpers (`as_exp_accurate`, `as_atanh_refine`, `as_tanh_zero`, `as_cosh_zero`,
  `as_sinh_zero`, `as_atanh_zero`, `as_*_database`, `as_logd`, `as_sinpipid`, ...). Each name exists in
  several copies (one per ifunc variant), and the copies with VEX code are the `_fma` ones. For all 62
  references from a function copy that contains no VEX instructions, the target copy has no VEX
  instructions either. The reverse also holds: the 14 references from VEX copies go to VEX copies. So the
  baseline (`_sse2` and plain) code paths do not reach VEX code.
- libmvec: the hits are AVX and AVX2 vector-ABI entry points (`_ZGVc*`, `_ZGVd*`, and their `_sse_wrapper`
  helpers). No function outside those names calls them, so only AVX-compiled code reaches them.

Decision: recorded as a known audit exception for ch5, not a build failure. The audit tool itself is not
changed here. Follow-up: teach `audit-isa.sh` the `_ZG[cde]` vector-ABI names and per-copy call analysis for
libm, then re-run. Tracked in BACKLOG under REBUILD-R2. Rule: CLAUDE.md section 5 ("known exceptions go into
the verification record with the log and the reason").
