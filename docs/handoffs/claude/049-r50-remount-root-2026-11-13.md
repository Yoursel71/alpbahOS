Task / status: r50 first record, BOOT-RO-ROOT-01 (real PC: black screen / freeze after "Reached Graphical Interface"). Host session, 2026-11-13.

Cause (found by Codex on the real install, session rollout-2026-11-13T11-24-27, reproduced in a QEMU copy of the SSD):
the installed system boots with `root=UUID=... ro`, but nothing pulls `systemd-remount-fs.service` into `sysinit.target`
(r4-root had no link in `/etc/systemd/system/sysinit.target.wants` or `/usr/lib/systemd/system/sysinit.target.wants`).
So `/` stays read-only: no persistent journal (that is why no logs ever appeared), `/etc/machine-id` opens read-only,
units that need a writable root fail, and the graphical session never comes up. Codex's fix on the installed disk was only
`ln -sfn /usr/lib/systemd/system/systemd-remount-fs.service /etc/systemd/system/sysinit.target.wants/`; after it the root
remounted rw, the journal appeared and sddm started in QEMU. Not yet proven on the real PC.

r50 record: `scripts/rebuild/r50/r50-root.sh all` -> snapshot `r4-snapshots/r4-before-r50`, record `alpbahos-remount-r50`
(one symlink), `alp check` 661 packages clean, `iso-gate --auto` PASS. Applied to r4-root 18:36.

Why r49 QEMU rows missed it: the matrix only checks that a session comes up and no unit failed; add a row/gate that the
installed root is `rw` (`findmnt -no OPTIONS /` has no `ro`) and `journalctl -b` is persistent. Also worth doing in r50:
a cheap gate in iso-gate that `sysinit.target.wants/systemd-remount-fs.service` resolves.

Earlier guess (nouveau/no NVIDIA choice) was not the cause of this freeze. Codex's other changes (persistent journald,
alpbah-boot-log.service, debug ISO) were diagnostics on the machine, not part of this fix.
