## 2. What broke, in order
1. First reboot after the NVIDIA install: no desktop. SDDM was on stock `DisplayServer=x11` with `CompositorCommand=weston --shell=kiosk`; X11 has no NVIDIA driver here and `weston` is not installed. Another Claude session fixed it by hand (`DisplayServer=wayland`, `CompositorCommand=kwin_wayland --drm --no-lockscreen --no-global-shortcuts --locale1`, backup `/etc/sddm.conf.bak`).
2. Second reboot (14:14): no desktop again. `/dev/nvidiactl` and `/dev/nvidia0` did not exist; `nvidia-smi` failed; the greeter's `kwin_wayland` (user sddm) died with SIGSEGV one second after start (coredump 14:14:29, core inaccessible). The udev rule's `nvidia-modprobe` and `nvidia-modprobe -c0 -u` both log "succeeded" but make no node. On the real devtmpfs `nvidia-modprobe -c0 -u` returns 0 and creates only `nvidia-uvm*`; in an isolated tmpfs `/dev` the same binary creates `nvidiactl` and `nvidia0` (rc 1). Cause inside the binary not found (no strace on the image). Fixed by tmpfiles (section 3).
3. Suspend: first try (before the 14:40 reboot) aborted with `Wakeup pending. Abort CPU freeze` (success 0, fail 1, errno -16, wake IRQ 28 = PCIe PME on 00:08.1); the retry worked. Probably a pending keyboard/USB event, not proven.
4. Boot time: about 2 min. Real wall time from the last log line of the old boot to the first userspace line was 139 s. The `usb 1-5` enumeration failures (4 x `device descriptor read/64 error -110`, power cycle, 2 x `not accepting address`, `unable to enumerate`) are a real cost: `usbcore.initial_descriptor_timeout` 5000 ms gave a "kernel" phase of about 67 s, 1000 ms gave about 33 s (total 1 min 53 s to 1 min 16-21 s). A line through the two points suggests about 8.5 s per 1000 ms plus a fixed part of about 24.5 s, so 200 ms would give about 26 s; the owner chose to keep 1000 ms (some slow devices may need more). My earlier "clock offset" theory was wrong.
5. Konsole showed empty boxes for `⎿` (U+23BF) and `⏵⏵` (U+23F5) from Claude Code: no installed font has those code points.
6. Flatpak Chrome (`com.google.Chrome`) showed only a close button: it ignores the GTK decoration layout.
